# bf-139 — Shareable URL: URL hash state encoding

## Status: COMPLETE (verified + bug fix applied)

The bulk of this feature was implemented in commit `4ad2e3a feat(bf-139)`
(already in HEAD) and its split-child `bf-2te7` (Copy share link — closed).
A prior retry produced further working-tree improvements that were never

## Requirement-by-requirement verification (code-level)

1. **On What If tag disable → `#without=og:image,twitter:card`** ✅
   - `showWhatIfPanel()` checkbox `change` handler calls `updateHash()`
     (app.js ~8645). `applyWhatIfChanges` (~8708) and `resetWhatIfToggles`
     (~8669) also sync the hash. `toggleWhatIfMode` off clears via
     `updateHash({ without: '' })` (~8566).
   - Encoding uses the internal dotted form (`og.title`, `twitter.card`)
     consistently for both write and `restoreHashState` decode (looks up
     `data-tag="${tag}"`), so round-trips are correct.

2. **On tab switch → `#tab=diagnostics`** ✅
   - `switchTab()` sets `currentTab` and calls `updateHash({ tab: tabId })`
     (~4961). Default tab `previews` is omitted from the hash.

3. **On compare mode → `#mode=compare&b=https://...`** ✅
   - Compare run calls `updateHash({ b: normalizedUrl2 })` (~5854); the `b`
     value is `encodeURIComponent`'d. `switchMode` calls `updateHash()` on
     compare exit (~684) so `mode=`/`b=` are dropped.

4. **On page load, parse hash and restore state** ✅
   - `restoreHashState()` (~523) runs in `DOMContentLoaded` (~596) after the
     `?url=` auto-inspect. Restores tab, compare second URL, and What If tags.
   - What If tags that arrive before `currentData` exists are stored in
   `pendingWhatIfTags` and applied via `applyPendingWhatIfTags()` once the
   progressive load finalizes (~955).
   - `progressiveLoad` now respects a `#tab=` restored on initial load via the
   `tabRestoredFromHash` flag instead of clobbering it with `switchTab('previews')`.

5. **'Copy share link' copies the full URL including hash** ✅
   - `shareResults()` copies `window.location.href` (includes the hash). The QR
   share URL (~5201) and the share-URL `pushState` update (~827) also preserve
   `window.location.hash` so generated links carry the state.

## Bug fixed in this commit

`updateHash()` previously did `history.replaceState(null, null, hash)` where
`hash` was `''` when all state was default. An empty-string URL resolves
against the current document URL and **preserves** the existing fragment, so
the hash was never cleared — switching back to the default tab, turning off
What If, or leaving compare mode left a stale `#tab=…` / `#mode=compare&b=…`
in the address bar, which a copied share link would then wrongly restore.

Fix: rebuild the URL from `window.location.pathname + window.location.search`
before appending the hash, so the `?url=` query param is preserved while the
fragment is correctly replaced (or removed when empty).

## Out of scope / not changed
- `getHashState()` parser uses `pair.split('=')`; values are `encodeURIComponent`
  on write (`b`) so embedded `=` survive round-trip. `without`/`tab` are simple
  identifiers needing no encoding. Left as-is.
