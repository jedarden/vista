# bf-520 — Accessibility: keyboard nav + screen reader support

## Outcome

Audited the full accessibility surface against the plan spec. Most of the
work was already in place (aria-live regions, `announce()`, a thorough
`prefers-reduced-motion` block, global `:focus-visible` ring, skip-link,
ARIA tab pattern, card-grid roving-tabindex + arrow nav, modal focus traps,
command palette). This bead closes the genuine gaps found during the audit.

## Changes

### 1. Live `prefers-color-scheme` tracking (`app.js`)
The system color-scheme was read **once** at init but never re-evaluated, so
flipping the OS theme at runtime left VISTA stuck. Added a
`matchMedia('(prefers-color-scheme: light)').addEventListener('change', …)`
that re-applies the theme on OS changes. It short-circuits once the user has
made an explicit choice (`localStorage['vista-theme']`), so a manual toggle
still wins.

To support that, `applyTheme` gained a `{ persist }` option (default `true` —
both existing callers unchanged). System-derived themes are applied with
`persist: false` so they stay transient and the listener keeps taking effect.

### 2. `prefers-reduced-motion` gap — image-diff shimmer (`style.css`)
`@keyframes loading-shimmer` is declared **after** the reduced-motion media
block in source order, so the in-block keyframe overrides could not win and
the image-diff loading shimmer kept animating under reduced-motion. Added an
explicit `animation: none !important` on `.image-diff-overlay::before` /
`.image-diff-side::before` inside the media block (the reliable fix for a
later-declared keyframe).

### 3. Mobile tap targets — 44×44px (`style.css`)
Several controls are intentionally compact on desktop (icon buttons at
~16–24px). Extended the existing `@media (hover: none) and (pointer: coarse)`
block to enforce `min-height: 44px` on the primary controls and `min-width: 44px`
on icon-only buttons (theme toggle, card toggles, dismiss ×, feedback FAB, etc.)
per WCAG 2.5.5 / 2.5.8.

## Verified already-complete (no change needed)

- **aria-live regions:** `#resultsAnnouncer` (polite) + `#errorAnnouncer`
  (assertive), driven by `announce()`, called on score changes, loading start,
  diagnostics, comparison completion, and sitemap results.
- **Icon-only buttons:** every rendered icon-only button already carries an
  `aria-label` (card theme/screenshot/context toggles, dismiss ×, copy, theme
  toggle, layout buttons). Emoji-leading buttons all have trailing visible
  text (e.g. "🔗 Share", "📋 Copy Code") — decorative emoji, accessible name
  from text.
- **Focus visibility:** global `:focus-visible { outline: 2px solid accent }`
  + `:focus:not(:focus-visible) { outline: none }`; form inputs use border /
  box-shadow focus indicators.
- **Keyboard-only workflow:** skip-link → nav → input → tabs (arrows + Home/End
  + roving tabindex) → card grid (arrows + roving tabindex) → modals (focus
  trap, Escape, focus return) → command palette (Cmd+K, arrows, Enter, Esc) →
  `role="button"` widgets (Enter/Space). No keyboard dead-ends found.
- **Color not the only indicator:** letter grades (A–F) + icons accompany all
  color-coded states.
