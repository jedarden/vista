## Acceptance criteria — verified against current `src/public/app.js`

1. **scoring-simulator.js is integrated and runs on editor content changes** ✅
   Wiring chain: `input` listeners bind `handleEditorInput` (app.js:6439) →
   debounced (300ms) `updatePreviewsWithEdits()` (app.js:6301-6303) →
   `applyRescore()` (app.js:6362) → `rescoreAllPlatforms()` (app.js:6340) →
   `scoreAll()` from the client `scoring-simulator.js`. `index.html` loads
   `scoring-simulator.js` before `app.js` (verified by
   test-editor-change-recalc.js).

2. **Full re-score of all 31 platforms happens (not just a counter)** ✅
   `rescoreAllPlatforms()` calls `scoreAll(modifiedMeta, currentData.imageProbe)`,
   which iterates the full PLATFORMS registry. test-full-rescore.js asserts the
   registry defines exactly 31 platforms, `scoreAll` returns a score entry for
   every one, and the passing/warning/failing summary sums to 31. The old
   "simple counter" placeholder in `recalculateScore()` is gone (asserted).

3. **New scores/grades are returned and stored for UI updates** ✅
   `applyRescore()` commits the result to `editorState.scoring` / `.meta`;
   `getCurrentScoring()` / `getCurrentMeta()` are the single source of truth the
   UI reads (falling back to `currentData` when there are no edits).
   `clearEditedScoring()` resets it on reset / fresh fetch. Verified by
   test-score-state.js ("stored scoring covers all 31 platforms").

4. **Performance: completes within 500ms for typical edits** ✅
   `applyRescore()` times the re-score into `editorState.lastRescoreMs`.
   Measured worst single re-score: **0.037 ms** across 20 runs — far under the
   500ms budget. test-score-state.js asserts `< 500ms`.
